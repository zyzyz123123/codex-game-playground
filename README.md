# 果园接接乐 — Codex 前端练习场

这是一个**故意没有做完**的桌面 Web 小游戏。

它的用途不是教大家手写 Git 命令，而是让产品同学用 Codex 完成一个直观的小功能，并在过程中真正经历：创建分支、提交改动、发起 PR、合并代码。

请把这个项目创建为一个大家都能访问的 **GitHub 仓库**。所有人从同一个 `main` 出发，在自己的分支完成任务，再通过 PR 把功能合回来。

## 现在能玩什么

V0.1 只有最小玩法：

- 用 `←` `→` 或 `A` `D` 移动篮子；
- 接住普通苹果；
- 每接住一个苹果增加 10 分。

炸弹、生命值、倒计时、游戏结束、金苹果、连击、暂停、音效和排行榜都**还没有实现**。这些就是留给练习者认领的工作。

## 运行方式

不需要安装任何东西，也没有后端。

1. 下载或 clone 仓库；
2. 双击 `index.html`；
3. 点击“开始接苹果”。

## 项目边界

请保持这个仓库足够简单：

- 只使用 HTML、CSS、JavaScript；
- 不引入框架、包管理器或构建步骤；
- 不增加后端、数据库、登录、远程接口；
- `index.html` 必须始终能够直接双击运行；
- 一次只完成 `TASKS.md` 中的一个任务。

## 让 Codex 帮你完成一个功能

先从 [TASKS.md](TASKS.md) 认领一个任务，再把下面这段话发给 Codex：

```text
请先阅读 README.md、AGENTS.md 和 TASKS.md。
我要完成 TASKS.md 中的“【粘贴一个任务名称】”，只做这一个任务。

开始改代码前，请先：
1. 检查当前 Git 分支和工作区状态；
2. 告诉我当前是不是 main 分支；
3. 说明这个功能完成后，我在页面上会看到什么；
4. 说明你预计修改哪些文件。

然后实现并验证功能。先不要 commit、push 或合并，等我确认页面效果。
```

看到效果并确认没有问题后，再告诉 Codex：

```text
请再次确认当前不是 main 分支。
把这一个任务整理成一个清楚的 commit，push 当前分支，并创建 PR。
请告诉我 PR 中改了什么、怎么验证。不要替我合并 PR。
```

## 一次练习的完整流程

```text
认领一个任务
  → 从 main 创建自己的分支
  → 让 Codex 只实现这一个任务
  → 在浏览器里验收
  → commit
  → push
  → 创建 PR
  → 让同事看一眼
  → merge
```

建议分支名使用 `feature/你的名字-任务`，例如：

```text
feature/xiaoming-golden-apple
feature/xiaohong-countdown
```

请坚持：**一个任务 = 一个分支 = 一个 PR**。

## 只需要理解的 5 个 Git 概念

- **Branch（分支）**：你自己的工作副本，不影响主版本。
- **Commit（提交）**：一次有名字、可追踪的改动记录。
- **Push（推送）**：把本地分支上传到 GitHub。
- **Pull Request / PR**：请求大家检查并把你的分支合进主版本。
- **Merge（合并）**：把某个分支的改动正式加入 `main`。

如果两个人碰巧改了同一处而发生冲突，不用慌。把报错交给 Codex，让它解释冲突双方分别改了什么，再由你决定保留哪一种结果。
